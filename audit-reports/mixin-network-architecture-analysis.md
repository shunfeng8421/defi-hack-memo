## 1. Architecture

### 1.1 Mixin Kernel (核心)

Mixin Kernel 是一个分布式数字资产账本，组合了四种技术：

| 组件 | 描述 |
|------|------|
| **UTXO 状态模型** | 类比特币的未花费交易输出模型——每笔交易独立验证 |
| **并行节点链** | 每个验证节点有自己的链，并行提议快照 |
| **BFT-DAG 共识** | 拜占庭容错 + 有向无环图——不需要单一区块生产者 |
| **集体签名** | 超级多数（2/3+1）节点联合签名确认每个快照 |

```
交易 → 验证缓存 → 快照 + 集体签名 → 节点轮次 → BFT-DAG + UTXO 状态
```

### 1.2 关键数字

| 参数 | 值 |
|------|:--:|
| 每快照最大交易数 | 255 |
| 最小共识节点数 | 7 |
| 拜占庭阈值 | 2n/3 + 1 |
| 新节点等待期 | 12 小时 |
| 轮次间隔 | 3 秒 |
| 引用窗口 | 30 秒（10 轮） |

### 1.3 技术栈

| 层次 | 技术 |
|------|------|
| 共识 | 自研 BFT + DAG |
| 存储 | Badger (LSM-tree KV 数据库) |
| 网络 | P2P (libp2p 风格) |
| 隐私 | MobileCoin 集成 |
| 治理 | Gnosis Safe 多签 |
| TEE | **不在仓库中**（关键缺失） |

## 2. 安全分析

### 2.1 🟠 关键关注点: TEE 不在源码中

Kernel README 明确说明: "The Trusted Execution Environment design is not integrated into this repository."

TEE 是 Mixin 安全模型的核心——它隔离了密钥操作。如果 TEE 实现有漏洞，整个网络的安全性取决于一个不在公开代码库中的组件。这是一个**信任空白**。

### 2.2 🟠 节点加入过渡期风险

新节点需要 12 小时才能获得完整共识权限。在这期间：
- 节点公钥不进入 `ConsensusKeys` 列表
- 但在最后 90 秒，pledging 节点可以增加非最终提案阈值
- 存在窗口期攻击：如果攻击者在 12 小时窗口内控制足够多的 pending 节点

### 2.3 🟡 最小节点数陷阱

如果活跃共识节点 < 7，`ConsensusThreshold` 返回 1000——实际上使网络不可用。这是一个**活性风险**：
- 节点退出可能触发连锁效应
- 恢复需要手动干预

### 2.4 🟡 MobileCoin 依赖

隐私功能依赖 mobilecoin-go（177MB 外部依赖）。MobileCoin 的故障或漏洞直接影响 Mixin 的隐私保障。

### 2.5 ✅ UTXO 模型优势

UTXO 模型天然隔离交易——每笔交易独立验证和最终化。这避免了账户模型的很多重入和状态冲突问题。

### 2.6 ✅ BFT-DAG 韧性

不需要单一区块生产者 = 抗审查。任何诚实节点都可以提议快照。DAG 结构确保即使部分节点宕机，网络也能继续运转。

## 3. 攻击面

| 向量 | 严重度 | 描述 |
|------|:--:|------|
| TEE 密钥泄露 | 🔴 | 如果 TEE 实现有漏洞，所有密钥暴露 |
| 集体签名合谋 | 🟠 | 2/3+1 超级多数合谋可双花 |
| 节点过渡期攻击 | 🟠 | 12 小时窗口期内控制 pending 节点 |
| 网络分区 | 🟡 | 分区恢复时的图分叉 |
| RPC 接口暴露 | 🟡 | 公共 RPC 可直接提交交易 |
| Go 内存安全 | 🟢 | Go 天然内存安全（非 C/C++） |

| 特征 | Mixin | Bitcoin | Ethereum | Solana |

| 状态模型 | UTXO | UTXO | Account | Account |

---

## 5. 结论

Mixin Kernel 是一个技术上独特的公链——UTXO + BFT-DAG + TEE 的组合在其他链上没有。其**安全性取决于不在公开代码库中的 TEE 组件**——这是最大的风险。共识设计在 ≥7 节点时稳健，但节点数降到 7 以下有活性风险。MobileCoin 集成提供隐私功能，但也引入了外部依赖风险。

**总体评级**: 7/10 —— 共识设计优秀，但 TEE 信任模型需要独立审计验证。
