## Finding 1: Platform Fee Self-Transfer — Accounting Bug

**Severity**: 🟡 MEDIUM | **Pattern**: #47 — Accounting Inconsistency

#### Description
`collectUsdcFromSelling()` transfers the platform fee to `address(this)` — the contract itself. Since the USDC is already held by the contract (deposited by the buyer in `buy()`), this is a no-op. The `totalFeesCollected` counter increments correctly, but the on-chain transfer is redundant and masks a conceptual flaw: fees should be transferred to a designated fee recipient, not recycled into the contract.

#### Vulnerable Code
```solidity
// NFTDealers.sol:181
function collectUsdcFromSelling(uint256 _listingId) external nonReentrant {
    Listing memory listing = listings[_listingId];
    uint256 fees = _calculateFees(listing.price);
    
    usdc.safeTransfer(address(this), fees); // ⚠️ self-transfer — no-op
    totalFeesCollected += fees;             // Counter incremented correctly
    
    uint256 amountToSeller = listing.price - fees + listing.collateral;
    usdc.safeTransfer(listing.seller, amountToSeller);
}
```

#### Impact
- **No direct fund loss** — USDC accounting remains correct
- **Gas waste** — unnecessary `safeTransfer` on every collection
- **Audit confusion** — suggests fees go somewhere, but they don't

#### Recommended Mitigation
```solidity
// Remove self-transfer; fee tracking is sufficient
function collectUsdcFromSelling(uint256 _listingId) external nonReentrant {
    // ... validation ...
    uint256 fees = _calculateFees(listing.price);
    totalFeesCollected += fees;
    // Fees stay in contract; withdrawn by owner via withdrawFees()
    uint256 amountToSeller = listing.price - fees + listing.collateral;
    usdc.safeTransfer(listing.seller, amountToSeller);
}
```

## Finding 2: Buyer Funds Locked Between `buy()` and `collectUsdcFromSelling()`

**Severity**: 🟡 MEDIUM | **Pattern**: UX / Fund Locking

`buy()` transfers buyer's USDC to the contract but the seller must separately call `collectUsdcFromSelling()`. If the seller never calls, the USDC is permanently locked — no timeout mechanism exists.

**Recommended**: Add claim deadline or automatic settlement after `BUYER_CLAIM_TIMEOUT`.
