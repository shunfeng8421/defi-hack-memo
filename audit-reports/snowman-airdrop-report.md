## Finding 1: EIP-712 TYPEHASH Typo — "addres" Not "address"

**Severity**: 🟠 HIGH | **Pattern**: EIP-712 Compatibility

#### Description
The `MESSAGE_TYPEHASH` contains a spelling error: `"addres"` instead of `"address"`. This renders the contract incompatible with all standard EIP-712 signing libraries (ethers.js, viem, web3.js). Users cannot generate valid claim signatures using standard tooling.

#### Vulnerable Code
```solidity
// SnowmanAirdrop.sol:49
bytes32 private constant MESSAGE_TYPEHASH = keccak256(
    "SnowmanClaim(addres receiver, uint256 amount)"  // ⚠️ "addres" typo
);

// Used in getMessageHash():
function getMessageHash(address receiver) public view returns (bytes32) {
    return _hashTypedDataV4(keccak256(abi.encode(
        MESSAGE_TYPEHASH,
        receiver,              // ← address, but TYPEHASH expects "addres"
        i_snow.balanceOf(receiver)
    )));
}
```

#### Impact
1. User tries to generate signature with ethers.js:
   `_signTypedData(domain, {SnowmanClaim: [{name:"receiver", type:"address"}]}, {receiver, amount})`
   → ethers hashes `"SnowmanClaim(address receiver,uint256 amount)"` ≠ contract's `"addres"`
2. Signature verification NEVER passes for standard tools
3. **Entire gasless claim feature is broken**

#### PoC
```solidity
function testTypo() public {
    bytes32 contractHash = keccak256("SnowmanClaim(addres receiver, uint256 amount)");
    bytes32 standardHash = keccak256("SnowmanClaim(address receiver, uint256 amount)");
    assertNotEq(contractHash, standardHash); // ← confirmed: mismatch
}
```

#### Recommended Mitigation
```solidity
bytes32 private constant MESSAGE_TYPEHASH = keccak256(
    "SnowmanClaim(address receiver, uint256 amount)"  // Correct spelling
);
```

## Finding 2: `claimSnowman()` Uses Current Balance — Not Snapshot

**Severity**: 🟡 MEDIUM | **Pattern**: Snapshot Timing

`getMessageHash()` uses `i_snow.balanceOf(receiver)` at CALL time, not at signature time. If the user's balance changes between signature generation and claim execution, the merkle proof may fail.

**Recommended**: Compute amount at signature time and include in the message.
