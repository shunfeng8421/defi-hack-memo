# Chapter Quality Gate — 必过 5 关

每章推送前，必须全部通过。任一不通过 → 不推送。

## Gate 1: 叙事锚点

- [ ] 开篇有真实攻击案例
- [ ] 案例包含: 协议名称 + 损失金额 + 日期 + 攻击概述
- [ ] 案例不是"X 协议损失了 Y 美元"——是有开始、中间、结尾的故事

## Gate 2: 代码深度

- [ ] 至少 3 个完整代码示例（漏洞代码 + 修复代码）
- [ ] 代码可以直接复制到编辑器运行
- [ ] 修复代码包含注释说明为什么这是正确方案

## Gate 3: 可执行性

- [ ] 至少有 1 个检查清单（Checklist）
- [ ] 检查项是具体可操作的，不是笼统的"注意安全"
- [ ] 每条给出具体检测方法

## Gate 4: 连接性

- [ ] 至少引用一个之前章节的概念
- [ ] 指出本章模式与其他模式的关系（例如"这和 Ch4 闪贷组合使用"）
- [ ] 引用了至少一个真实损失金额

## Gate 5: 字数

- [ ] 核心章 (Part I/II): 5,000+ 词
- [ ] 领域章 (Part III/IV): 2,000+ 词
- [ ] 防御章 (Part V): 2,000+ 词
- [ ] 用 `wc -w` 统计确认
- [ ] Ch1-3 标准 (7,500-9,100词) 是目标，不是天花板

---

## 自检流程

```
写完 → 读一遍 → 过 5 关 → 不通过 → 补充 → 再过关 → 通过 → 推送
```

没有任何章节可以跳过。包括今天已经写好的章——如果有不达标的，明天重写。
