# 深度案例 55-60 — 高价值攻击

## 55. Bybit $1.5B (2025-02)
**史上最大单笔加密货币盗窃**

攻击链:
1. 攻击者攻破了Safe{Wallet}开发者机器
2. 注入了恶意JavaScript代码到Safe前端
3. Bybit团队在Safe界面签名了一笔"正常"交易
4. 实际执行的是修改了Bybit冷钱包代理合约的实现地址
5. 新实现合约没有multisig限制 → 攻击者转走全部401,347 ETH

**核心教训**: 不是合约bug → 是前端+供应链攻击
**模式**: #13 (权限滥用) + 社会工程
**防御**: 多人多设备验证；硬件钱包屏幕确认；tx模拟

## 56. Wormhole $320M (2022-02)
**Solana→Ethereum桥验证绕过**

攻击链:
1. 攻击者在Solana端提交了虚假的guardian签名
2. `verify_signatures()`未检查签名是否来自有效guardian
3. Solana端接受了伪造消息 → mint了120,000 ETH
4. 攻击者将ETH从Wormhole桥取出

**模式**: #34 (跨链签名验证)
**代码级**: Solana程序中缺少签名者清单元数据验证
**防御**: 验证所有guardian签名；审计跨链消息格式

## 57. PancakeBunny $120M (2021-05)
**闪贷 + 代币增发攻击**

攻击链:
1. 闪贷借入大量BNB (PancakeSwap)
2. 将BNB存入Bunny池 → BNB价格瞬时下跌
3. `getReward()`计算基于操纵后的价格 → 增发巨额BUNNY
4. 在PancakeSwap上倾销所有BUNNY → 价格崩盘
5. 还闪贷 + 保留利润

**模式**: #1 (闪贷+价格操纵) + 代币经济学缺陷
**防御**: TWAP价格预言机；代币增发上限

## 58. Uranium $50M (2021-04)  
**AMM Swap精度问题 — 50/50池**

攻击链:
1. 不同步balanceOf和内部会计
2. `swap()`在转账前用当前balance乘以比例计算输出
3. 攻击者反复swap → 累积精度偏差 → 池子被抽空

**模式**: #7 (AMM储备操纵) + #46 (精度损失)
**防御**: 转账后更新储备；使用balanceOf而非内部变量

## 59. Beanstalk $182M (2022-04)
**闪贷治理攻击**

攻击链:
1. 闪贷借$1B BEAN代币 (占总量67%)
2. 用借来的代币投票通过BIP-18恶意提案
3. 提案执行 → 将所有协议资金转给攻击者
4. 还闪贷 (提案要求返还流动性)

**模式**: #8 (闪贷治理) — 经典案例
**防御**: 投票锁定期；快照投票而非实时投票；时间锁

## 60. TeamFinance $15.8M (2022-10)
**升级引入新漏洞**

攻击链:
1. v2→v3合约升级
2. v3误删了v2中的代币总量验证(`maxMintAmount`)
3. 攻击者发现漏掉 → 调用mint无限增发
4. 耗尽了池中的所有流动性

**模式**: #13 (升级) — 升级引入的安全回归
**防御**: 升级前后完整性检查；不变性模糊测试
